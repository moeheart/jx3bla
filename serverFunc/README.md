## 洛阳之战英雄难度接收

25 人英雄洛阳之战沿用 `/uploadCombinedData`：客户端以 URL 编码表单的 `jdata` 字段提交 `{"data": [...]}`，其中 `type=replay` 为个人复盘、`type=battle` 为整场统计。完整 25 人通关记录通常包含 25 份个人复盘和 1 场战斗；失败场不加入客户端上传队列。旧的 `/uploadReplayPro`、`/uploadActorData` 接口仍兼容。

- 地图与首领定义共用 `tools/Names.py`。英雄地图为 `836`；`ActorStat.mapdetail` 保存 `836`，`ReplayProStat.mapdetail` 保存 `25人英雄洛阳之战`。当前正式服样本按战斗时间归入游戏版本 `161`，不会与普通 `835` 混榜。
- 返回每条请求的 `id`，并为个人复盘返回 `shortID`。客户端回填编号后清空成功队列；请求失败保留队列。重复提交沿用既有编号，不重复分配公开链接。
- 接收时保留统计 JSON 中的技能轴、机制统计和属性质量。缺失装备、未建模属性等质量限制继续作用于表现分、rDPS、mrDPS 排名；成功接收不代表自动取得精确排名资格。
- `/getMaps`、`/getBossesFromMap` 提供英雄入口；`/getBattle` 和 `/getReplayPro` 回读已保存数据。`/getRank` 使用英雄地图全名，名人堂 `/getHoFRank` 使用映射后的 `836`。

离线接收回归：`python -m unittest discover -s tests -p test_luoyang_heroic_upload.py -v`。设置 `JX3BLA_HEROIC_LOG_DIR` 为本地 2026-11-13 英雄日志目录后，还会重放五场通关，验证客户端实际请求、Flask 表单解析、125 份独立个人编号、回读和重复上传。测试禁止外网连接，数据库和保存文件均使用内存替身，不会上传玩家数据到生产环境。
