# 9.0 桌面界面预览

在主界面点「导入日志…」，选择同一副本的一组日志。分析完成后双击战斗，单击团队表的角色名可进入个人复盘。整场轴在「时间轴」，个人轴在「个人复盘 → 个人时间轴」。「重点记录」适合快速复盘，切到「全部记录」可以核对细节。团队总结和战斗记录保留在本次会话内。

五奶和花间采用各自分析器记录的技能与状态。其余有个人结果的 DPS 和坦克读取日志中能归属到角色的原生施放、招式命中和技能效果，同一时刻的同技能多目标结算合并显示。若全场只有效果结算，重点视图保留最常见的三种效果，详情标出事件来源。只有日志直接记录的施放才进入「施放」轨道。

## 启动与输入

预览客户端使用 Qt 6，可直接运行 Windows 单文件 EXE。在源码环境安装仓库依赖后运行以下命令。

```powershell
python -m pip install -r requirements.txt
python MainWindow.py
```

可读取 JCL 和既有的文本型 `.fstt.jx3dat`。遇到 CNDK 二进制日志会提示使用 JCL。窗口按屏幕工作区布局，窄窗口中的导入、分析、监听及停止按钮会排列成两行。日志分析和网络请求在后台处理。主界面显示自动上传的状态和待传数量，首次试用如需只在本地复盘，可先在设置里关闭自动上传。

## 验收方式

沿用[清理前记录的实录基线](../160/cleanup-replay-baseline.json)，分三个会话依次导入普通五场、11 月 13 日英雄六场（含先失败后通关）、11 月 14 日英雄三场。每场先核对输入 SHA-256，再比对通关依据、起止和有效时长、装备状态、伤害守恒、团队表、技能指标、首领时间轴及个人上传候选数。验收模式在本地禁止网络访问。

下面的 PowerShell 命令从仓库根目录运行。三个分组分别为 `normal`、`heroic13`、`heroic14`，每组指向含对应原件的目录。对单文件客户端使用相同参数。

```powershell
$env:PYTHONHASHSEED = '0'
python MainWindow.py --validate-desktop --baseline docs/160/cleanup-replay-baseline.json --group normal --log-dir . --report build/qt9-acceptance/source-normal.json
```

逐场验收经过正式的导入队列、分析线程及结果窗口。每场打开六个团队页，并遍历每位队员的五个个人子页。每组回执记录战斗数、实际打开的页面及分析期间 Qt 事件循环响应次数。本轮实录来自洛阳之战，较早赛季首领的站位图和在线账号服务未纳入这组实录验收。

## 2026 年 11 月 26 日验收结果

源码和 Windows 单文件预览分别跑完相同的 14 场。每轮均为 13 场通关、1 场失败，共打开 350 份个人复盘、1,750 个个人子页。13 场通关产生 325 份个人上传候选，整组验收均在本地运行。两种入口的逐场结果与基线一致。[实录与构建回执](桌面实录验收.json)

实录还发现首领击败后仍有公告和脱战事件，旧整场轴最长多出 65.779 秒。预览版将整场和通用个人轴裁剪到分析器确认的起止时间，专业个人轴采用各自分析区间。14 个整场轴、266 个通用个人轴和 84 个专业个人轴已逐一核对显示及导出边界。

同一台 Windows 机器上通过了 100%、125%、150%、200% 缩放和 670 × 415 紧凑主窗检查。首次同意协议后可以进主窗、保存设置并在重启时读回。拒绝协议则退出。Python 回归 548 项和 JavaScript 回归 8 项全部通过。
