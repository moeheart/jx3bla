# 9.0 桌面战斗复盘

启动后在「战斗记录」上方选择记录角色，可输入角色名搜索。程序从正式服安装位置发现本机角色，列出其日志目录里所有 JCL 和历史文本型 .fstt.jx3dat。多个角色可能共享一个账号日志目录。使用备份日志时可点「选择目录」。设置中的「正式服目录」用于手动指定安装位置。

标准 JCL 在解析前按文件名换算本机时间。自定义文件名或历史格式无法识别开战时间时，暂用文件修改时间；打开复盘后显示日志内部记录的时间。

| 想做什么 | 操作 |
| --- | --- |
| 查看已有战斗 | 选中或双击「未解析」的战斗开始分析。按 Ctrl 或 Shift 可选择多场，程序按时间顺序处理。 |
| 下次直接看复盘 | 完整结果自动保存。重启后双击「已解析」的行可以直接打开，也可用「重新解析」更新。目录变化会自动刷新。 |
| 分析之后产生的新战斗 | 点「自动解析新战斗」。停止监听后仍可手选目录里的战斗。临时导入其他位置的文件可用 Ctrl+O。 |
| 查看角色表现 | 在战斗团队表点击角色，或在个人复盘顶部搜索队员。个人页集中显示主要指标、装备与奇穴、心法专项和技能轴。 |
| 核对战斗机制与数值 | 整场时间轴列出首领机制与点名，略去普攻和「常规技能」标记。数值统计在玩家名下按所选口径绘制背景条，选中队员后，下方两表分别在技能名、目标或增益来源名下按总量绘制背景条。 |
| 查看或导出时间轴 | 整场按时间折行，每行一根刻度轴。点同名技能可查看逐次时间和目标，在「导出」中可保存整图。个人轴可横向拖动，顶部显示点名与首领机制，接着是占用及不占用 GCD 的施放、持续治疗覆盖与引导等指标。有治疗价值的资源技能单列冷却条。 |
| 标记本地战斗 | 战斗记录可增减分、复制、补充说明，团队总结按队员汇总本目录已解析战斗的批注。 |
| 设置上传 | 主界面显示自动上传状态，可在设置里关闭。打开已存复盘不会再次上传。 |

结果保存在程序配置旁的 `cache/replays.sqlite3`。删除该缓存将丢失本地复盘和批注，原日志仍可重新解析。文件大小、修改时间、解析设置或缓存格式发生变化时，目录会重新显示「未解析」。个人身份绑定保留在设置中，经验、等级和升级入口已从客户端撤下。新治疗复盘展示 rHPS、技能数据和百分位。

团队表按全程 rDPS 绘制玩家背景条。各职责的百分位均对照 JX3 Logs 玩家榜，按战斗时的赛季、同难度、同首领和同心法读取线上 rDPS 分布。悬停可查看样本数和装备估算等质量说明。缺少对应分布的战斗显示「暂无线上样本」。已保存的复盘可在新的排名分布到达时刷新百分位。装备摘要列出有效套装档位、白字和黄字精简及特殊武器。悬停「强化」可查看全身附魔等各项含义。[版本更替时的更新指南](版本更替时的更新指南.md)

云裳心经和补天诀的个人页同时显示「仅 GCD 效率」和「战斗效率」。前者统计占用公共调息的时间，后者还计入回雪飘摇或醉舞九天的引导。激活吉光时，每次回雪施展也计入 GCD。两项都以有效治疗战斗时间为分母，重叠时段只计一次。

## 本地启动与验收

```powershell
python -m pip install -r requirements.txt
python MainWindow.py
```

支持 JCL 和既有文本型 JX3DAT；CNDK 二进制请改用 JCL。指定实录目录可使用以下命令验证目录列表、逐场解析、重启后直接打开及恢复所有个人页。验收使用临时配置、独立缓存和禁网模式。

```powershell
python MainWindow.py --validate-desktop --group library --pattern '2026-11-26-14-*.jcl' --player 迷你花花 --log-dir <实录目录> --report build/qt9-library/source/library.json
```

原 14 场仍使用清理时记录的[实录基线](../160/cleanup-replay-baseline.json)。新旧装备摘要及移除的治疗评分单独对照，战斗边界、输出治疗、通关判定、技能轴及个人上传候选数继续比较。示例命令如下。

```powershell
$env:PYTHONHASHSEED = '0'
python MainWindow.py --validate-desktop --baseline docs/160/cleanup-replay-baseline.json --group normal --log-dir . --report build/qt9-library/normal.json
```

11 月 26 日预览的 [构建与实录验收回执](目录与复盘验收.json) 记录了单文件包的哈希、目录缓存重启验证、三组旧实录及测试数量。六份记录中装备和百分位的逐场差异见[装备与百分位核对](装备与百分位核对.md)。

## 首次 Qt 迁移的历史验收（1d3a7ac）

源码和 Windows 单文件预览分别跑完相同的 14 场。每轮均为 13 场通关、1 场失败，共打开 350 份个人复盘、1,750 个个人子页。13 场通关产生 325 份个人上传候选，整组验收均在本地运行。两种入口的逐场结果与基线一致。[实录与构建回执](桌面实录验收.json)

实录还发现首领击败后仍有公告和脱战事件，旧整场轴最长多出 65.779 秒。预览版将整场和通用个人轴裁剪到分析器确认的起止时间，专业个人轴采用各自分析区间。14 个整场轴、266 个通用个人轴和 84 个专业个人轴已逐一核对显示及导出边界。

同一台 Windows 机器上通过了 100%、125%、150%、200% 缩放和 670 × 415 紧凑主窗检查。首次同意协议后可以进主窗、保存设置并在重启时读回。拒绝协议则退出。Python 回归 548 项和 JavaScript 回归 8 项全部通过。
