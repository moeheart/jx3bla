# 苍生铸世 50 级心法属性来源审计

## 结论与范围

本次直接从 `C:/SeasunGame/Game/JX3_EXP` 的 `1.6.0.9503 / zhcn_exp` 客户端解包心法脚本。已验证现有 **31 个职业代码、32 个心法技能**（藏剑包含问水、山居），并保留原始字节码、可读结果、完整 `AddAttribute` 调用及哈希。永久心法属性使用实际心法 Lua；客户端装备面板 Lua 用于交叉检查，发生冲突时不覆盖心法脚本。

这份审计负责属性来源，不把原件验证等同于服务器最终伤害验收。新模型、实际日志回放和旧赛季回归结果另见接入手册。

`xinfa50.json` 顶层字段为 `game_edition=160`、`player_level=50`、`client_version`、`occupations`、`alternate_xinfa`。每个职业包含：

- `skill_id` / `skill_level`：真实心法技能与学习等级。
- `learning_source`：门派学习表路径、哈希与完整命中行。
- `raw_attributes`：依顺序保存每条 `AddAttribute(mode, enum, value_a, value_b)`；这是完整来源。
- `base_attributes`：可识别的永久 `at*` 基值；同一词条的多条调用相加。
- `conversions`：中文来源主属性、目标属性、伤害系、原始数值、分母 1024、系数及原枚举名。
- `source`：原件路径、字节数、SHA256。
- `original_bytecode_matches_decompiled` / `decompiler_issue`：反编译交叉检查的结果。

`summed_enum_attributes` 仅供审计浏览。事件 ID、标记等离散枚举可能有多次调用，**不能把该汇总直接当作游戏属性输入**。运行时应选取 `raw_attributes` 中已明确语义的属性，或消费对应规范化字段。中文“会心”转换的目标是会心等级，不是直接百分比。

## 原始字节码与等级验证方法

1. 通过当前 `skills.tab` / `skills2.tab` 按心法名定位技能与 `ScriptFile`，再用 `jx3decrypt/unpack.exe` 实际解包。隔离输出位于 `backups/luoyang-20260915/attribute-verification`；未向 jx3decrypt 仓库写入。
2. 对 20 个门派的 `settings/skill/SkillAutoLearning/*.tab` 重新解包。32 个选中技能均在玩家 **50 级学习第 5 重**；生成器从原表选择等级并断言，未用 `skills.tab` 的历史 `MaxLevel=14` 代替。
3. 当前字节码是 Lua 5.1、32 位 `size_t`。执行环境是 Lupa 2.8 的 Lua 5.1，生成器只将字符串长度字段改为宿主所需的 64 位；指令和数值常量不改。每份原件都先通过 `serialize(4) == original` 的逐字节回环断言。
4. 在禁用文件、系统和 Python 主机入口的 Lua 环境中，预装实际 `kungfuConst.lh`，从实际 `Skill.lh` 取出 `AdditionalAttribute`，以 `dwLevel=5` 执行 `GetSkillLevelData`，只捕获属性调用。
5. 另用仓库已有 `unluac.jar --rawstring` 生成可读源并同条件执行。**32 个原始脚本均成功；31 个反编译脚本完全一致；明尊原件成功而反编译版本因 `L2_2` 为 nil 失败。** 明尊数据来自原件，未人工修补反编译结果再冒充原件。

4 份坦克触发 Lua 的原件本身是 GB18030 文本；清单明确标为文本转码，没有把它们描述成反编译字节码。

## 分母、公共属性与永久心法实例

**两类分母不可混用：** GlobalParam 的通用力道/元气转攻击等字段使用千分制；心法 `*_TO_*_COF` 使用 1024。原始 `role_attribute.lua` 的 SHA256 为 `162d3e5041f08419cc22f6f6f0d3c54315b6d72537313ca166ae70b85301b0cb`，以下为其根函数的零起始指令位置：

| 心法 | 当前心法 Lua 原始数值 | 原始面板 Lua 的绑定 |
| --- | --- | --- |
| 离经 | 根骨转治疗 686；根骨转混元会心 82 | pc530 `BaseHealPlus=0.669921875`；pc533 `BaseCritPlus=0.080078125`；pc534 绑定 `lijing` |
| 云裳 | 根骨转治疗 727；根骨转阴性会心 41 | pc503 `BaseHealPlus=0.7099609375`；pc506 `BaseCritPlus=0.0400390625`；pc507 绑定 `yunshang` |

离经永久治疗为 6367，云裳为 6822；离经两条内防 280 与 273 必须合并为 553，不能被后一条覆盖。公共 `AdditionalAttribute` 给非坦克增加 `DECRITICAL_DAMAGE_POWER_BASE_KILONUM_RATE=102`，没有再增加一份根骨转会心。通用根骨转会心 `250/1000` 和心法会心转换分别来源于不同层，模型应分别应用。

角色默认基础值可由原始面板 Lua 的 R54 表支持：体质 18、力道 17、身法 18、根骨 18、元气 17、额外生命 3956。JCL 没有角色体型或裸装面板字段，因此这里是当前面板默认基础，不声称已分别实测每种体型。

内功武器白字转攻击不能全心法共用。`role_panel_evidence.json` 的原始指令确认，武器均伤乘 6、外攻乘 1 的转换只在幽罗分支；现有 31 个职业不应因此平添一份内攻。

## 会效字段及未证实边界

- `atUnlimitCriticalDamagePowerKiloNumRate`：当前 29 条记录。香梅 32676.1 的原值 102 对应文本会效 +10%；2757 的 256 对应 +25%；30137 的 410 对应 +40%。数值按 `raw/1024` 加到会效，不能当作等级乘区。字段名区分了不受普通上限限制的部分，但这些 Buff/文本本身不能证明原生结算上限和截断先后。
- `atMagicCriticalDamagePowerPercent`：当前只有 15475.2，原值 1500，文本“会心效果提高15%”，与万分制一致。当前原始面板 Lua 没有该字段；没有据此把它和 `BaseKiloNumRate` 混为一个分母，也没有声称已从原生函数证明全部乘区、上限行为。
- `atTherapyPowerBasePercentAdd`：当前资源表、jx3decrypt 当前导出目录、32 个心法和公共/面板 Lua 未出现实例。不能仅凭字段名认定与 `atTherapyPowerPercent` 同一乘区；保留捕获入口不代表语义已证实。
- 反编译文本不是权威执行结果。明尊的反编译失败、4 个 UI 冲突均显式记录。
- 本次未运行游戏进程，也未通过实时裸装/有装面板逐体型验收；JSON 的来源验证状态表示取证完成，不表示全部服务器内部取整与上限都已实测。
