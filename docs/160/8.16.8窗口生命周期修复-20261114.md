# 8.16.8 窗口生命周期修复

继续使用8.16.8，修复奶歌及共用窗口入口在打开、关闭复盘时出现的`TclError: invalid command name "...canvas"`。

## 原因与复现

此前`Window.start()`每次创建一个后台线程执行`loadWindow()`。Tk主循环可以在两次绘图调用之间销毁窗口，但后台线程仍继续向已销毁的Canvas写入。同一玩家的按钮复用一个窗口对象，重复点击还会启动多个线程、交错覆盖`self.window`；旧窗口的关闭回调因此可能销毁新窗口。

在Python 3.14.0、Tk 8.6.15下使用真实奶歌复盘，经原有`start()`和真正的`mainloop()`复现了上述两种问题。正常路径执行234次`create_image`；绘制时关闭本窗稳定触发与用户相同的异常；重复打开后关闭旧窗，旧窗仍存在而新窗被销毁。旧代码快照和匿名时序保存在忽略的`build/validation/window-lifecycle-20261114/`，原始玩家数据未提交。

上一次窗口验证直接调用`loadWindow()`，覆盖了控件布局和滚动，却遗漏了实际入口的线程及关闭竞争。本轮新增真实入口回归。

## 修复

- 主窗口创建Tk时注册调度器。后台线程仅向Python队列提交打开请求；控件创建、图像绘制和共用关闭处理均在Tk所属线程执行。每处理一个请求便交还事件循环，避免连续绘制整个批次阻塞关闭操作。
- 同一复盘已打开时只显示并置前现有窗口。关闭会取消此前排队的打开请求，延迟关闭绑定具体窗口，避免影响之后重新打开的窗口。
- 外部销毁同步更新存活状态；个人复盘加载失败清理半成品并允许重开。只有确认窗口或Tk根窗口已销毁时，才把相应Tcl异常视为关闭取消；仍存活窗口上的数据或绘制错误继续正常报告。
- 战斗事件记录和加锅窗口的自定义关闭方法接入安全关闭流程，保留分锅保存及状态重置业务。本轮没有迁移自行覆盖`start()`的设置窗口及文件选择器，也没有修改分析、装备、有效时间、上传或排名计算。
