# 50 级装备属性取证

来源为 2026-09-15 体服客户端 `1.6.0.9503`，装备、附魔、套装主表使用
`equip/resources/cangshengtf`；额外解包均写入
`backups/luoyang-20260915/equipment-verification`，没有修改客户端与 jx3decrypt 源目录。

## 已确认并修复

- 装备底表已经压缩。例如 `7,111692` 的体质 348、根骨 165、内功攻击 228，
  直接计入，不能再整体套用 130 级到 50 级的压缩因子。
- 精炼倍率仍为 0、0.5%、1.3%、2.4%、3.8%、5.5%、7.5%、9.8%、12.4%。
  `role_attribute.lua` 原始字节码根函数 R47 保存该表，child 22 的 PC 113–132
  将 Magic 词条乘以 `1 + R47[精炼等级]`；child 0 为四舍五入函数。
  `StrengthableAttrib.tab` 指定可精炼词条，白字武器伤害、攻速与白字基础防御不精炼。
- 配装导出存五行石等级 1–8，导入误当物品 ID 使其全部变成 0。共享导入方法现在
  同时接受等级与旧五行石物品 ID，保留完整导出/导入往返。
- 普通附魔读取所有四条属性；脚本、技能事件、秘籍 ID 不作为面板数值相加。
  旧版本鞋附魔 11272 的固定治疗 241 不再用于 50 级。
- 套装按 `2_1..2_4` 等实际列名读取每档全部效果，修复原来每档两个效果的错误假设。
  例：套装 633 的效果是 2、4、6 件，不能错认成 2、6 件；套装 650 的两个 2 件效果均保留。
- 五彩石仅从主武器读一次，同时检查有效孔数量与等级总和。例如物品 25469 当前对应
  附魔 5625：16 颗/总等级 90 激活根骨 104；18 颗/总等级 108 激活治疗系数 102。
  无效孔不能参与激活计数。
- 内功武器原始内功攻击和白字分别输出。例如 `8,46253` 是混元攻击 860、
  近战白字基础 43、浮动 28、攻速 16。装备层不将白字再加到攻击，面板层统一处理。

## 镶嵌的本季缩放

当前 `attrib.tab` 的孔属性 8145、17832 等仍为 225，与旧版相同。
直接沿用旧版 8 级倍率 2.6 会每孔增加 585，遗漏了本季的额外缩放。

当前客户端 `role_attribute.lua` child 22 的 PC 166–169 调用
`item.GetSlotAttrib(SlotIdx, Level)`，PC 172 读取 `Param0`，再经取整函数累计。
Lua 没有直接给出镶嵌倍率；实际规则已从同一客户端的 `SO3ItemHouseX64.dll`
确认。`KGLuaItemInfo::LuaGetSlotAttrib` 的 RVA `351F0` 经 RVA `23B90` 读取孔词条，
再调用 RVA `216C0`；实际物品 `KGItem` 的对应虚函数也进入同一个计算函数。

原生计算顺序如下，只有 `StrengthableAttrib.tab` 的 `Value1Strable=1` 才缩放 Param0：

1. 等级不高于 6：`factor = level × 0.195`。
2. 等级 7–8：`factor = (level × 0.65 - 3.2) × 1.3`。
3. 使用双精度依次计算 `原始孔值 × factor × 1355 / 27800`，最后向零截断。

1355 和 27800 是当前原生函数的常量，不读取单件物品的品级、品质或角色需求等级。
因此，225 点孔属性的 1–8 级结果依次为 **2、4、6、8、10、12、19、28**。
代码保持原生运算顺序，避免提前取整引入误差，也不再对普通装备底表进行二次压缩。

## 验证与重现

`python -m unittest tests.test_cangsheng_equipment -v` 的 11 项回归覆盖精炼白字边界、
宝石导入、1–8 级原生镶嵌结果、缩放标记、负值向零截断、附魔、多档套装、五彩石双条件、
无效孔与未知物品。

`python -m tools.ValidateCangshengEquipment <备份后的JCL> --output <备份目录内JSON>`
只读取玩家装备事件，验证实际物品覆盖与宝石往返。今天最后一份史朝义日志含 25 名玩家、
299 件有效装备、449 颗五行石，物品均可定位。报告仅写心法、匿名序号、属性与来源哈希，
不写玩家姓名或角色 ID。此项是输入覆盖验证，并非逐项游戏面板实测。

额外解包原件哈希记录在 `equipment-verification/source-evidence.json`。

`equip/resources/cangshengtf/native_gem_evidence.json`。使用
`python -m tools.check_cangsheng_native_gem` 可离线复核精简证据；加上
`--source backups/luoyang-20260915/native-item-audit/SO3ItemHouseX64.dll`
可与隔离备份的原 DLL 核对。DLL 本身不纳入源码或发行包。
