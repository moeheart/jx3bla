# 8.16.8 英雄二、四、五号通关判定修复

本轮修正11月14日英雄洛阳之战的三场漏判，继续使用8.16.8。上一轮装备核算已完整，但这三场的`win=0`让战斗与个人复盘上传提前返回，因此无法进入正常接收流程。此前“没有捕获旧规则中的通关证据”不代表战斗实际失败。

表内时刻均为JCL原生毫秒。二号本体有效伤害与严格反射合计248200000，四号合计428580000，均与本体血量上限一致；五号对应终段伤害445340166，与独立通关对照的70%血量终段一致。这些伤害数字用于旁证，运行判定不依赖固定血量或百分比。

本体Battle血量存在网络量化，也可能在结束时恢复满血。它既不能当作精确逐点余血，也不能通过“低血量+脱战”直接判胜。全团脱战、移除气劲、一般奖励、插件分享和日志文件结束均不单独判胜。此次荣誉消息的使用范围来自原始事件交叉验证，没有将未取得的客户端授予条件代码当作已证实机制。

## 判定规则

普通/英雄洛阳二、四、五号保留原有宝箱、本体死亡、精确完成消息等证据，并增加以下联合判定：

1. 只接受`MSG_SYS`中完整匹配当前难度的`赛季荣誉[25人普通/英雄首领击伤·入门/精通]：n/15或n/25`，阶级与分母对应且进度合法。
2. 对应真实本体实体在近期受到玩家有效正伤，荣誉位于该伤害之后5秒内；同一本体最终脱战与荣誉相差不超过5秒。
3. 后续伤害、重新进战或本体场景重现使候选失效；显式重置/失败截止之后的荣誉不能把之前的退出改成通关。
4. 正常延迟到达、位于战斗事件列表末尾之后的System消息仍可使用；以本体脱战时刻确定结束，不把荣誉延迟或文件尾录加进战斗时间。

荣誉本身不含首领名，所以不能独立判胜或挪用其他实体的伤害/退出。未知荣誉类型和其他副本不推广。日志缺少必要结束链，或通关后同一本体又重进战且没有原有强证据时，仍保留未确认；本轮不为覆盖此类额外情形移除否决条件。

## 验证与发布

完整回归运行**488项**，耗时721.736秒：487项通过、1项既有窗口生命周期测试在批量运行中超时，零错误、零跳过。该窗口模块独立复测13项全部通过，最终无未解决失败；运行源码指纹稳定。三场最新英雄均以`seasonal_boss_credit_and_combat_exit`确认通关，完整生成75份精确个人复盘；3个实际Tk战斗表/统计窗、rDPS数值与排序、技能轴/点名边界、原生表单发送至隔离接收端、存储回读及重复编号检查均通过。原始文件SHA、直接及主目标伤害总量与修复前一致。

原有五场英雄、125份个人复盘的完整接收回归通过。四号最终真实解析36场：3场通关、33场失败，零误胜/漏胜，源码稳定。98份原生日志交叉扫描中，11月13日英雄44份只有5份通关含精确荣誉，11月14日32份同样只有5份；其余失败/杂兵记录没有该通知。二号8份、五号8份原始结束链也独立留档，含血量量化、尾部续战等不能泛化的反例。匿名证据见[目录](evidence/heroic_victory20261114/README.md)，完整验收见[回执](heroic-victory-20261114-validation.json)。

正常客户端在`win=0`时不会加入战斗或个人上传队列，所以本次三场修正后按首次接收进入服务端，后续重复上传保持原编号。没有为手工伪造的旧失败结果放宽同版覆盖保护，也没有修改接收协议或数据库旧记录。

服务器发布结果将在同步验收后补入。原始日志、角色身份和实际上传正文只用于本地隔离验证，不提交或上传生产。
