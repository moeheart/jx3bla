# 阆风悬城接入手册

## 1. 范围

本手册只记录“阆风悬城”副本的接入信息，不包含其它副本。

当前版本的实现范围是：

- 已接入副本名：`阆风悬城`、`25人普通阆风悬城`、`25人英雄阆风悬城`
- 已接入普通本首领：`笑妆娘`、`唐醉`、`柳公子`、`阿史那承庆`
- 已接线但未完成阶段 2-4：`唐怀仁`
- 已接线但未完成挑战本：`鲁念雪`、`千机源枢`

本轮已完成普通本 1-4 的阶段 1、阶段 2 与阶段 3。

## 3. 结构约定

- `replayer/boss/langfengxuancheng/` 下每个首领文件都保持独立。
- 不再使用 `Common` 作为首领逻辑公共骨架。
- 如需共用，只允许使用很薄的辅助工具；当前共用辅助仅限 `WinEvidence.py`，只负责取证过滤与报告格式化，不承载首领逻辑。

## 4. 通关判定优先级

接入时采用以下优先级：

`喊话 > 特定 NPC 重伤 > 宝箱出现 > 其它稳定场景信号 > 总伤害弱兜底`

补充约束：

- 体服早期没有喊话是正常现象，所有首领都要预留喊话接口。
- `总伤害达到血量阈值` 只能作为弱兜底。
- 一旦使用宝箱作为主判定，必须同时保留血量兜底。

## 5. 宝箱规则

宝箱判定使用 **名字**，不使用模板 ID。

原因：

- 不同人数和难度会对应不同宝箱。
- 最多可能出现 36 个版本。
- 只认模板 ID 后续维护成本过高，而且容易漏。

当前代码中，宝箱名按首领独立维护，例如：

- `笑妆娘宝箱 / 笑妆娘寶箱`
- `阿史那承庆宝箱 / 阿史那承庆寶箱`

## 9. 后续更新时的优先动作

当体服或正式服有新日志时，优先重复以下流程：

1. 先跑 `tools/LangfengStage2Evidence.py` 重新取证。
2. 检查是否出现了新的明确喊话。
3. 检查是否出现了稳定的特定 NPC 重伤。
4. 如果有更高优先级信号，用它替换当前的 scene/damage 方案。
5. 宝箱规则继续优先用名字维护，不要改成模板 ID。
